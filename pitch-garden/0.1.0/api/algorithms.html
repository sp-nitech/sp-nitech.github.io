pitch_garden.algorithms#

The algorithms are chosen by their names, e.g., pg.Tracker("rapt"), and their parameters are given as the fields of their configurations, e.g., pg.Tracker("rapt", fmin=60.0).

class pitch_garden.algorithms.base.AlgorithmConfig(fmin: float | None = None, fmax: float | None = None, device: str = 'cpu')[source]#

The base configuration shared by all algorithms.

Each algorithm defines its own configuration by inheriting this class and adding algorithm-specific fields.

crepe#

class pitch_garden.algorithms.crepe.CrepeAlgorithm(config: AlgorithmConfig)[source]#

CREPE: a convolutional representation for pitch estimation (Kim et al., 2018).

The model and the weights are those of torchcrepe. Unlike torchcrepe, no dither is added to the pitch, so the results are reproducible, and the audio is resampled by soxr instead of resampy.

fcn-f0#

class pitch_garden.algorithms.fcn_f0.FcnF0Algorithm(config: AlgorithmConfig)[source]#

FCN-f0: a fully-convolutional network for pitch estimation of speech signals.

This is proposed by Ardaillon and Roebel (2019). The frames are normalized and analyzed one by one as FULLCONV=False of FCN-f0, unlike the default of FCN-f0 analyzing the whole audio at once with the normalization by sliding windows, so that any frame period is available.

fcpe#

class pitch_garden.algorithms.fcpe.FcpeAlgorithm(config: AlgorithmConfig)[source]#

FCPE: fast context-based pitch estimation (Luo et al., 2025).

The model and the weights are those bundled in torchfcpe. The frames are analyzed every 10 milliseconds for any frame period. The outputs are at the hops as trained in FCPE, although the windows are centered 80 samples after the hops. The whole audio is analyzed at once because the group normalization of the model uses the statistics over all the frames.

class pitch_garden.algorithms.fcpe.FcpeConfig(fmin: float | None = None, fmax: float | None = None, device: str = 'auto', voicing_threshold: float = 0.006, num_threads: int | None = None, weights_path: str | None = None)[source]#

Configuration of FCPE.

harmof0#

class pitch_garden.algorithms.harmof0.HarmoF0Algorithm(config: AlgorithmConfig)[source]#

HarmoF0: logarithmic scale dilated convolution (Wei et al., 2022).

The models and the weights are those of HarmoF0. The frames are analyzed every 46 samples, i.e., about 2.9 milliseconds, for any frame period, because the convolution over the frames is trained on such dense frames, e.g., a hop of 10 milliseconds degrades the accuracy considerably. Unlike HarmoF0, the frames are centered at multiples of the hop, the dynamic range of the log spectrogram is limited relative to the maximum of the whole audio instead of every 1000 frames, and the batches of frames overlap so that the results are independent of the batch size.

pienet#

class pitch_garden.algorithms.pienet.PiENetAlgorithm(config: AlgorithmConfig)[source]#

PiENet: the pitch estimation network (Airaksinen et al., 2019).

The model and the weights are those of GTE-AUG in PiENet, which is trained with noise augmentation for robustness. The frames are analyzed every 10 milliseconds, with which the convolution over the frames is trained, for any frame period, and the batches of frames overlap so that the results are independent of the batch size.

straight#

class pitch_garden.algorithms.straight.StraightAlgorithm(config: AlgorithmConfig)[source]#

STRAIGHT: the F0 extraction based on multiple cues (Kawahara et al., 2005).

This uses pylstraight, a Python port of Legacy STRAIGHT. See takenori-y/pylstraight for details. The voicing decision is made inside the algorithm, and thus the voicing score is not provided. Note that the voicing decision relies on the contrast with silent segments.

yaapt#

class pitch_garden.algorithms.yaapt.YaaptAlgorithm(config: AlgorithmConfig)[source]#

YAAPT: yet another algorithm for pitch tracking (Zahorian and Hu, 2008).

This uses AMFM_decompy, a Python port of YAAPT. See bjbschmitt/AMFM_decompy for details. The voicing decision is made inside the algorithm by dynamic programming, and thus the voicing score is not provided. The warnings and the messages of AMFM_decompy are suppressed.
